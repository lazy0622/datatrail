## 本轮回答什么

在相同 SQL 工具执行器、同一公开 Olist 数据、同一模型和预算下，区分“提供业务治理信息”和“增加代码粒度守卫”的作用。**这是受控的 SQL 工具层实验，不是完整 DB-GPT UI/ReAct 多工具 Agent 的端到端评测。**

每组 20 题，包含一题不支持的优惠券减免金额问题，因此数值 SQL 指标的分母为 19。最终 JSON 回答与预写参考值比较，金额绝对容差 0.005，保留 NULL 与行顺序，不把数值字符串默认为数值。

**没有观察到新增守卫的自然任务增益。** C 组守卫触发 0 次，B→C 错变对 0 题、对变错 0 题。不能把 A→C 的三题差异归给代码，也不能从零触发声称检出率或误拦率很好。

## 三题差异与题目语义边界

A→B 和 A→C 的差异是 H05、H07、H12。A 选择按送达时间归属，金标准及治理文档按下单时间归属；H07 还出现先得到按下单时间的结果、随后改成送达时间及字符串金额的轨迹。

这些原题没有全部显式写明“按下单时间”，存在合理的时间口径歧义。因此 **17/20 是对预设业务合同的符合度，不是三次普遍事实错误或通用模型准确率**。结果说明显式业务信息的重要性，但这批题不能单独分离“信息增加”和“模型推理改进”。本轮保留原题，没有看到结果后改题、改答案或重跑替换。下一版本应把明确口径题和必须澄清题分开封存。

## 本轮同时交付的改造与验证

`commerce_grain.py` 将同作用域 SUM 的金额列匹配扩展到算术、COALESCE、CAST、ROUND 等表达式，排除内层 SELECT 的列。新增针对性回归，不对任意 SQL 或合法金额分摊作正确性证明；其保守复核仍可能要求合法查询改写。

数据诊断、工具安全、复用、表达式和评测合同的相关回归合计 **128 项通过**。这包含 9 个新增表达式/作用域用例和 8 个评测合同用例，属于限定测试集，不是全仓全部检查。

还发现了一个评测采集问题：SQLAlchemy Row 不是普通 tuple，初版用 `default=str` 落盘后成为元组字符串，导致辅助 SQL 指标初算为 0。现从原始保留字符串安全还原并重新判分，同时修正未来采集为数组、增加真实 SQLAlchemy Row 回归。**未重新请求模型或重跑 SQL，最终回答评分不受此问题影响。** 原始日志与原始运行器 hash 保留；公开摘要区分原记录和修正字段。

## 复现与产物

本机在仓库根目录、已配置 `.env.local` 和 Olist 数据后：

```powershell
python examples/commerce_audit/evaluation_v1/run_comparison.py --arm A
python examples/commerce_audit/evaluation_v1/run_comparison.py --arm B
python examples/commerce_audit/evaluation_v1/run_comparison.py --arm C
python examples/commerce_audit/evaluation_v1/summarize.py
```

每组设置和逐题记录位于忽略上传的 `output/datatrail/evaluation-v1/`。运行器拒绝混用不同 hash 的实验；由于采集修复改变了运行器 hash，现有旧目录会被拒绝续写，不能覆盖冒充同一次实验。重新实验请另存整个旧输出目录，在新的输出中运行并标为新批次，保留两组结果。

跨机器重建 SQLite 时文件字节 hash 可能不同；需新建实验版本、重新核对两套参考 SQL 和数据 hash，不应改写本版封存题集来绕过检查。`freeze_cases.py` 对已有题集拒绝覆盖，并设定参考 SQL 查询超时。冻结预检曾发现一条替代 CTE 查询超时，已在封存前换成等价的订单相关汇总，之后两套结果一致。

公开 `RESULTS.json` 包含逐题判分、SQL 调用、token、时间与失败，未上传密钥或原始 Olist 数据。下一步优先补明确时间口径与澄清行为的独立题、真实自然扇出坏例、误拦和完整 Agent 的停止预算实验。
