# 自主迭代 01：重复查询与业务解释边界

日期：2026-11-07。模型继续使用 `deepseek-flash`，开启思考，使用官方默认 High。目标是减少已观察到的重复数据库执行，并给模型补充明确的数据解释边界。

## 问题与验收

先前真实模型轨迹中，相同的成功查询被重复提交；已有 SQL 工具每次都会访问数据库。Flash High 的后续样例只执行一次 SQL，也不足以证明重复执行问题稳定消失。

本轮对静态公开 Olist 数据源做有限改造：

- 同一 Agent 轮次的完全相同 SQL，可复用首次成功结果和原证据编号。
- 并发提交同一 SQL，只执行一次；不同 SQL 使用各自的锁。
- 失败、取消不缓存；新一轮重新读取；随机、时间、未知函数不复用。
- 只有静态示例 `olist_ecommerce_demo` 的普通分析路径启用；看板与其他数据源保留原行为。
- 开关为 `DATATRAIL_QUERY_REUSE=0/1`，与粒度复核开关分开。

这不是跨请求缓存，不提供变化数据源的缓存一致性，也没有实现 SQL 语义等价识别。SQL 内部空白、注释、别名等变化可能不命中复用。复用减少数据库执行，不保证模型停止重复发起工具请求或减少模型 token。

|---|---:|---:|---:|---|
| 关闭复用 | 5 | 5 | 0 | 6159 单，867953.46 BRL |
| 开启复用 | 5 | 1 | 4 | 完全一致 |

这是受控回放，不是自然模型任务准确率或线上延迟提升。

```powershell
python examples/commerce_audit/replay_query_reuse.py --db examples/dashboard/olist/data/generated/olist.db --output output/datatrail/query-reuse-replay.json
```

回放还发现 SQLGlot 把 AND / OR 也表示为 Func。最初的保守函数白名单因此漏掉了带状态和时间过滤的实际查询。本轮已修正，并新增带 AND / OR 的聚合回归；回放入口会检查验收条件，不能仅“脚本正常退出”就算优化有效。

## 业务解释边界

在静态 Olist 分析上下文中明确：

1. `price` 与 `freight_value` 分开解释；字段名不能证明折扣券、税费、退款口径。
2. 全量关联诊断与当前月份的统计不是同一范围。
3. 查询观察与原因假设分开陈述，金额变化不自动证明优惠券等业务因素。

这部分是提示上下文修正，不是任意自然语言业务断言的程序化验证器；仍需用真实输出及独立任务检查其效果。

## 保留的未完成样例

扩展到“比较 7/8 月金额、订单、客单价，并讨论优惠券归因”的开发提问，模型做了 10 条不同的 SQL 探索，还尝试知识检索与代码计算。客户端在 128.23 秒附近按本次预算关闭请求，未收到最终完成事件，因此不计为完整任务成功。

已保存轨迹中没有相同 SQL 的重复提交，不能把这次耗时归结为重复查询，也不能期待本轮精确查询复用缩短所有长任务。部分查询采用日期函数，按本轮保守白名单不会复用。本次记录为“开发客户端预算截止、任务未完成”，不冒充服务崩溃或模型业务准确率结论。原始轨迹在 `output/datatrail/iteration-01-live.json`。

另一次直接询问 price 是否已扣优惠券及是否支持优惠券归因，模型仍进行了多次工具探索，客户端在 102.59 秒附近按预算关闭，未收到最终完成事件。轨迹在 `output/datatrail/iteration-01-evidence-smoke.json`。因此，本轮只确认业务证据上下文已注入，尚不能声称无依据解释问题已修复。后续需要收敛工具选择、探索预算与停止条件，再复测完整回答。
